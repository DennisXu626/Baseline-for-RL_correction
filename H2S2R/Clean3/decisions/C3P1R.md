## 方法裁定：保留PCA和初态，有限扩展动作范围并标定零动作

不改300行PCA语料、5维、B、mu、原分位数据和PCA文件SHA，不混入GraspPose，不改变静态初态、奖励、参考或PPO架构。只在Clean3动作解码侧增加单独、有SHA的范围校准侧车。这个有限动作范围扩展是明确的方法适配，不是实施者擅自放宽，也不能继续把运行范围叫“纯示范0.5/99.5分位”。

对左右手分别计算，全部向量按5维逐元素：

```
x0 = B @ q0_hand                 # 已批准名义静态初态，只计算/冻结一次
L  = pca.minimum + B @ mu        # 原绝对任务坐标范围
U  = pca.maximum + B @ mu
w  = U - L
Lr = min(L, x0 - 0.05*w)
Ur = max(U, x0 + 0.05*w)
target(a) = x0 + a*(x0-Lr)       # -1 <= a <= 0
          = x0 + a*(Ur-x0)       #  0 < a <= 1
```

保留完整原示范区间，并仅在初态附近预注册5%原宽度的双向余量，避免一侧动作成为完全死区。使用现有`rescale_from_policy_centered`，不增加累积残差、在线reanchor、按物体追踪的GraspPose或每步重新设default_config。controller原有reset静态姿态吸引项保留，披露为shared-static-posture初始化/控制条件；不宣称这些初态信息只影响第一帧而随后彻底消失。名义零点与范围全训练固定；外评初态±0.005rad扰动不触发重新拟合/扩大范围。

CPU计算最大范围宽度倍数右2.0814、左4.3329。这不是可以忽略的数值变化，必须在运行manifest和结果中报告。超出示范分布的可控性留给本包物理门；禁止再扩大范围或调5%余量。零动作只消除手PCA目标不匹配，不代表重力下无运动。

掌6维也必须采用已批准静态FK作为固定零点，沿用既有V12有界绝对掌目标解码与可达范围；不复制右瓶特有中心值。不得伪造掌范围通过，初态若不在机器人已有可达范围内则提前交付，不改机器人/参考摆位。两侧实际FABRICS每控制步各set_targets一次、每物理子步各advance一次。
